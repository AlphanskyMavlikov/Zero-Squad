# Contractor Matcher V2

## Новое
- Semantic matching: OpenAI `text-embedding-3-small`, а не keyword matching.
- Embeddings работают только после hard filters.
- Полная декомпозиция score.
- ИИ-агент генерирует объяснение из структурированных evidence-данных, текст не захардкожен.
- Воронка причин отсева.
- «Почему не этот подрядчик?» с конкретными причинами.

## Запуск
1. Python 3.10+
2. `pip install -r requirements.txt`
3. Задайте ключ в Windows PowerShell:
   `$env:OPENAI_API_KEY="ваш_ключ"`
4. `streamlit run app.py`

Можно также запустить `run.bat` после задания переменной среды.

## Архитектура
`CSV → город+категория → HARD FILTERS → embeddings → score → TOP 3 → AI explanation`

Hard filters: дата, бюджет, формат, опционально язык и длительность.
Embedding similarity никогда не отменяет hard filters.

## Детерминизм
Сортировка: total score DESC → semantic similarity DESC → id ASC.
При одинаковых данных и моделях порядок стабилен.

## API
API используется только для semantic embeddings и объяснений. Embeddings кэшируются локально в `embeddings_cache.json`, поэтому повторные запросы не пересчитывают уже известные описания.

## Исправление StreamlitSecretNotFoundError

Версия не обращается к `st.secrets`, если файла `secrets.toml` нет.
Ключ читается только из переменной среды `OPENAI_API_KEY`.

### Вариант 1 — PowerShell
```powershell
$env:OPENAI_API_KEY="sk-proj-ВАШ_КЛЮЧ"
streamlit run app.py
```

### Вариант 2 — SET_API_KEY.bat
Запустите `SET_API_KEY.bat`, вставьте ключ в консоль и нажмите Enter.
Ключ намеренно не записан в исходный код или ZIP.

## V3: три режима отбора

### Hard
Строгий режим: цена не выше бюджета; выбранный язык обязателен; длительность должна полностью покрываться.

### Medium
Умеренно гибкий режим: допускается цена до **15% выше бюджета** и до **15% нехватки по длительности**. Язык становится мягким критерием и влияет на объяснение/рейтинг, но сам по себе не исключает кандидата.

### Light
Гибкий режим: допускается цена до **30% выше бюджета** и до **30% нехватки по длительности**. Язык также мягкий.

Во всех трёх режимах **дата, город, категория и формат мероприятия остаются обязательными**. Semantic embeddings по-прежнему запускаются только после соответствующего режима фильтрации.

Карточка показывает, какое именно послабление позволило кандидату пройти отбор. AI-агент получает `selection_mode` и `relaxed_conditions`, поэтому объясняет это динамически, а не шаблонным текстом.


## Автоматический API-ключ

В этой версии приложение автоматически читает:

`.streamlit/secrets.toml`

Первый раз запустите:

`НАСТРОИТЬ_API_ОДИН_РАЗ.bat`

Вставьте **новый** OpenAI API key. Скрипт локально создаст:

```toml
OPENAI_API_KEY = "sk-proj-..."
```

После этого при всех следующих запусках достаточно открыть:

`ЗАПУСТИТЬ.bat`

Повторно вводить ключ не нужно.

`secrets.toml` намеренно отсутствует в ZIP и добавлен в `.gitignore`: секретный ключ не должен храниться в распространяемом проекте или GitHub.

## V4 API check
`НАСТРОИТЬ_API_ОДИН_РАЗ.bat` теперь только сохраняет ключ и не запускает Streamlit.
После этого запускайте `ЗАПУСТИТЬ.bat`. В sidebar появилась кнопка `Проверить подключение OpenAI`.
401, проблемы квоты/rate limit и сети отображаются понятным сообщением вместо traceback.


## Исправление подписей режимов
Интерфейс теперь использует название фактически выбранного режима:
- `после Hard-отбора`;
- `после Medium-отбора`;
- `после Light-отбора`.

Сообщения о пустой выдаче и блок «Почему не этот подрядчик?» также используют текущий режим вместо универсальной надписи `hard filters`.


## Clean UI
Из пользовательского интерфейса убраны технические служебные сообщения:
- подпись про то, что embeddings запускаются после выбранного режима отбора;
- блок с технической цепочкой `CSV → City+Category → ...`.

Логика pipeline при этом не изменена — убрано только её отображение пользователю.
